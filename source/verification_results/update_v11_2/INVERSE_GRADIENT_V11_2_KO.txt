2. 낮은 TAC에서 유효한 시작점을 놓치는 문제

V11.1은 2색 시작점 3개 중 점수상 유효한 하나를 골라 좌표 탐색을 시작했다.
100% TAC 반례에서 독립적으로 역산한 양끝색 seed의 전체 경로 TAC가 100.78%여서
제외되었다. 이 seed의 모든 RGB 채널을 단 1코드씩 높이면 TAC 100.00%가 되는데,
기존 탐색은 이 유효하고 더 나은 후보를 놓쳤다. 기존 반환값의 최종 TAC 보정은
0회였으므로 원인을 '최종 TAC 보정 때문에 악화'라고 설명해서는 안 된다.

V11.2는 다음을 수행한다.

- 기존 V11.1 방식의 2색 결과를 그대로 baseline 후보로 남긴다.
- 독립 역산 양끝색, 목표 양끝색, 흰색 seed 각각을 모든 양자화 상태의 TAC가
  만족될 때까지 RGB 채널을 1씩 밝히는 방식으로 유효화한다.
- 유효화한 seed 자체와 그 seed에서 따로 최적화한 결과를 모두 후보로 남긴다.
- 각 결과는 전체 양자화 경로의 TAC 보정까지 끝낸 뒤 같은 목적함수로 비교한다.
- 선택된 2색뿐 아니라 기존 baseline 2색에서 만든 3색 시작점도 남긴다.
  독립 역산 양끝색+중간색, 원래 목표 3색, 흰색이라는 기존 3색 시작점도 유지한다.

목적함수는 변경하지 않았다.
33개 샘플의 ΔE76 제곱 가중평균(양끝 가중치 2, 나머지 1)
+ 0.2 × 최대 ΔE76 제곱.

최종 TAC 보정 후에 baseline과 비교하므로 새 시작점을 추가했다고 이전 결과의
이 목적함수가 더 나빠지지 않는다. 평균 ΔE만 단독 최소화하거나 전역 최적해를
증명하는 알고리즘은 아니며, 잔여 색차는 그대로 표시해야 한다.

4. reference_support(model, rgb) 계약

입력은 원본 ICC를 해석한 sRGB의 단일 RGB triplet 또는 (...,3) 배열이다.
단색 역산 RGB 결과에는 추천 RGB를, CMYK 결과에는 해당 CMYK의 sRGB 해석값을,
그라데이션에는 최종 선택 후보의 추천 input_samples를 전달해야 한다.
목표색 또는 모델 적용 후 predicted RGB를 넣는 계약이 아니다.

photo 모드의 two_stop/three_stop에 각각 reference_support 객체를 추가했다.
ICC 모드에서는 reference_support:null이다.

반환 필드:
  total_samples: 전체 표본 수
  neutral_samples: D65 Lab C* <= 16인 중성·저채도 표본 수
  chromatic_samples: C* > 16인 표본 수
  near_samples: 유채색 중 d <= 12 AND d < model.radius
  transition_samples: 유채색 중 d > 12 AND d < model.radius
  extrapolated_samples: 유채색 중 d >= model.radius
  near_percent / transition_percent / extrapolated_percent:
    chromatic_samples를 분모로 계산하여 소수점 2자리 반올림.
    chromatic_samples가 0이면 세 값 모두 null. 0% 정확도나 검증 완료를 의미하지 않는다.
  percentage_denominator: 'chromatic_samples'
  neutral_chroma_max: 16.0
  near_delta_e76_max: 12.0
  extrapolated_delta_e76_min: 현재 model.radius (기본 26.0)
  near_requires_local_support: true
  metric: 'Delta E 76, sRGB-derived D65 Lab'
  meaning: 입력색의 사진 기준점과의 근접도이며 예측 정확도가 아니라는 설명

d는 활성화한 source_rgb 기준점까지의 최소 ΔE76이다.
모델 반경이 12보다 작은 사용자 설정에서도 d>=radius를 외삽으로 먼저 분류하여
세 범주가 겹치지 않는다. 기준점이 전혀 없으면 모든 유채색을 외삽으로 분류한다.
빈 입력이나 중성색만 있는 입력은 percent null이며, 각 sample count는 0 또는 실제 수다.
근처/전이/외삽은 사진으로 검증된 인쇄 정확도, 성공확률, 색역 판정이 아니다.

주의: 기존 top-level extrapolated_sample_percent는 호환성 때문에 남아 있지만
V11.1의 d>12 / 모든 33개 표본 계산이다. 새로운 UI는 이 값을 쓰지 말고 선택된
two_stop 또는 three_stop의 reference_support를 사용해야 한다.

실제 대칭 3색 사례에서 새 2색은 33개 모두 중성·저채도이므로 percent null이다.
3색은 유채색 33개 중 근처15/전이14/외삽4이며 45.45%/42.42%/12.12%다.
따라서 2색/3색 선택과 지원범위 표시가 반드시 함께 바뀌어야 한다.

5. 이미지 방향/선택 좌표 계약

공통 analysis 추가 필드:
  source_image_size: [width,height]
  source_coordinate_system: pixel centers; origin top-left; x right; y down
  css_angle_convention: 0 degrees up; 90 degrees right; clockwise

자동/영역 분석은 기존 css_angle 계산 규칙을 유지한다.
analysis.rect는 원본 이미지에서 [left,top,right,bottom]이며,
rect_coordinate_convention은 left/top 포함, right/bottom 제외를 명시한다.

선택한 두 점 분석은 기존 css_angle:null을 유지한다.
두 점을 연결하는 선의 방향은 이미지 전체 그라데이션 방향을 추정한 값이 아니기 때문이다.
기존 source_points의 원본 픽셀 좌표를 그대로 보존하고 다음을 추가했다.
  source_points_normalized: 각 점을 [x/(width-1), y/(height-1)]로 정규화
  source_points_normalization: 위 규칙, 길이1 축의 분모는1
  source_line_css_angle: 선택한 첫 점→둘째 점의 방향(소수점4자리)
  source_line_angle_scope: 전체영역 각도 추정값이 아님을 설명
  preview_css_angle: 90.0 (선택선 색 샘플은 가로 strip으로 미리보기)
  line_sample_count: 33
  line_sampling: 반올림 픽셀 중심의, 이미지 경계에서 잘린 5x5 영역 중앙값

선택선 좌표, 정규화 좌표, 원본 크기, 원본 선 각도, 가로 미리보기 각도를
구분하여 재현할 수 있다. 정방향/역방향 선택선의 샘플 색과 각도 반전도 확인했다.

6. 유지되는 모델·사용 범위

추천 그라데이션은 encoded sRGB 선형 보간이며 stop은 0/100 또는 0/50/100%다.
CMYK stop 변환값이 전체 CMYK 보간 그라데이션 최적해를 의미하지 않는다.
임의의 stop 개수/위치나 공간적으로 비선형인 목표 전체를 정확히 재현하는 기능을
추가한 것은 아니다. 최종 파일에 같은 프로필/보간 조건을 적용한 뒤 다시 확인해야 한다.
사진 기준색 근접도와 잔여 ΔE는 같은 사진 모델 내부의 설명이며 실물 측색/RIP 검증과 다르다.
